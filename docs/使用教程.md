# 串口 Hub + Codex MCP 使用教程

## 1. 架构（必读）

从 **0.2.0** 起，拆成两个角色，**共用同一个 COM 口和同一份日志**：

```text
┌─────────────────────────────────────┐
│  Serial Hub（常驻，只起一个）         │
│  · 独占 COM1                        │
│  · 网页 http://127.0.0.1:8080       │
│  · WebSocket :8081（长连、可自动重连）│
│  · HTTP API（给 MCP 用）            │
│  · 环形日志：网页 / AI / 下位机      │
└──────────────▲──────────────────────┘
               │
     ┌─────────┴─────────┐
     │                   │
 浏览器网页            Codex MCP（瘦客户端）
 发/看消息             write_data / read_data
                       不 open COM，只访问 Hub
```

| 进程 | 怎么起 | 做什么 |
|------|--------|--------|
| **Hub** | `scripts\start-hub.bat` 或 `start-serial-hub` | 占串口、网页、日志 |
| **MCP** | Codex 按配置自动起 `start-serial-mcp` | 调 Hub API，**不要**再手动起一份占串口的旧服务 |

**错误用法（会 PermissionError 13 / 读不到日志）：**

- 命令行起一个「占 COM 的 MCP」+ Codex 再起一个 MCP  
- 关掉 Hub 却指望网页还在  

**正确用法：**

1. 先起 **Hub**，保持窗口不关  
2. 浏览器打开网页，连 COM  
3. 再开 Codex（MCP 自动连 Hub）

## 2. 本机第一次安装

```powershell
cd "F:\AI\串口MCP\umeko_serial_mcp"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -e .
```

确认入口存在：

```powershell
dir .\.venv\Scripts\start-serial-*.exe
```

应能看到：

- `start-serial-hub.exe`  — 常驻中枢  
- `start-serial-mcp.exe`  — 给 Codex 的瘦客户端

## 3. 日常使用步骤

### 步骤 A：启动 Hub（网页不断连的前提）

```powershell
cd "F:\AI\串口MCP\umeko_serial_mcp"
.\scripts\start-hub.bat
```

看到类似输出后**不要关这个窗口**：

```text
网页:  http://127.0.0.1:8080
API:   http://127.0.0.1:8080/api/health
```

浏览器打开：<http://127.0.0.1:8080>

- 右上角 **WebSocket: 已连接（长连）**  
- 断线会自动重连，保持标签页打开即可  
- 刷新页面会拉最近约 200 条历史日志  

### 步骤 B：网页连接串口

1. 点 **刷新串口**，下拉选择例如 `COM1`  
2. 编码选 **GBK**（中文 / XCOM 常见）  
3. 波特率 `115200`  
4. 点 **连接**  

状态应变为：`串口: COM1 (gbk)`

网页底部可发送，日志显示 **`[人类/网页 发送]`**。

### 步骤 C：配置 Codex（只需一次）

编辑 `C:\Users\<你>\.codex\config.toml`：

```toml
[mcp_servers.serial-mcp]
command = 'F:\AI\串口MCP\umeko_serial_mcp\.venv\Scripts\start-serial-mcp.exe'

[mcp_servers.serial-mcp.env]
SERIAL_MCP_HUB = "http://127.0.0.1:8080"
```

保存后**重启 Codex**。

> MCP 进程**不会**再打开 COM，只会访问 Hub。  
> 因此可以与网页同时使用 **同一个 COM1**。

### 步骤 D：在 Codex 里操作

**查状态 / 扫口：**

```text
用 serial-mcp 的 hub_status 和 list_ports
```

**连接（若网页已连可跳过，Hub 上已是连着的）：**

```text
用 serial-mcp connect_port 连接 COM1，115200，encoding=gbk
```

**AI 发送（网页应出现 [AI Agent 发出]）：**

```text
用 serial-mcp 的 write_data 发送：hello stm32
```

**读取网页发过的内容 + 下位机回传：**

```text
用 serial-mcp 的 read_data 读取新日志
```

返回示例：

```text
[用户/网页] ping
[下位机] PONG
[AI] hello stm32
```

可多次 `read_data`：使用游标增量读取，**不会**因为读过就从 Hub 删掉（网页仍能看到完整历史缓冲）。

## 4. 日志标签对照

| 网页显示 | 来源 |
|----------|------|
| `[AI Agent 发出]` | Codex 调用了 `write_data` |
| `[人类/网页 发送]` | 网页输入框发送 |
| `[下位机 返回]` | 串口收到的数据 |
| `[系统]` | 连接/断开/编码等 |

若你希望 AI 标记却看到「人类/网页」，说明消息是从网页发出的，不是 `write_data`。

## 5. 网页长连说明

- WebSocket 每 15s 发 `ping`，服务端 `pong`  
- 断开后 1s～10s 退避自动重连  
- 切回浏览器标签会尝试重连  
- **Hub 进程必须一直运行**；关 Hub = 网页与 MCP 都失效  
- 可选开机自启 Hub：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-hub-autostart.ps1
# 取消：加 -Remove
```

## 6. 常用环境变量

| 变量 | 含义 | 默认 |
|------|------|------|
| `SERIAL_MCP_HUB` | MCP 连接的 Hub 根 URL | `http://127.0.0.1:8080` |
| `SERIAL_MCP_HTTP_PORT` | Hub HTTP 端口 | `8080` |
| `SERIAL_MCP_HOST` | Hub 监听地址 | `127.0.0.1` |
| `SERIAL_MCP_ENCODING` | 默认编码 | Windows=`gbk` |
| `SERIAL_MCP_BUFFER_MAX` | 环形缓冲条数 | `5000` |

```text

GET  /api/status
GET  /api/ports
```

```powershell

```

## 8. 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 网页拒绝连接 | Hub 没开 | 运行 `start-hub.bat` |
| COM PermissionError 13 | 两个进程抢口 / XCOM 占口 | 只保留一个 Hub；关 XCOM 或换虚拟对端 |
| Codex `无法连接 Serial Hub` | Hub 没开或 `SERIAL_MCP_HUB` 错 | 先起 Hub，检查 env |
| `read_data` 无新数据 | 游标已追上 / 确实无新日志 | 网页先发一条再读；或看 `hub_status` |
| 中文乱码 | 编码不是 GBK | 网页或 `set_encoding gbk` |
| 改代码不生效 | 旧进程 | 重启 Hub；重启 Codex（重载 MCP） |

---

## 9. 推荐工作流（STM32 / 日常）

1. 插上板子 / 虚拟串口  
2. 启动 Hub，打开网页，连 COM1 + GBK  
3. 打开 Codex  
4. 网页手动调试命令；需要 AI 时让 Codex `write_data` / `read_data`  
5. 全程看同一网页日志  
6. 下班可关 Codex；**Hub 可一直挂着**方便网页不断连
